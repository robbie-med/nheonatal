# Numbers audit — September 2026

Written for anyone (human or AI) picking this repo up later. It records where
every clinical number in the app comes from, how that was verified, what was
wrong before, and how to re-check it.

Commit with the fixes: `43010ca` on branch `claude/inspiring-faraday-p4ardf`.

---

## TL;DR

| Area | Before | After |
|------|--------|-------|
| EOS risk (both models) | Least-squares fit to 57 scraped rows; up to 75% off at the edges of the input range | KP's published coefficients; matches every scraped KP value to 0.01/1000 |
| EOS recommendations | Invented thresholds on posterior only (0.5 / 1 / 3) | KP's own logic, confirmed against the live KP calculator |
| EOS incidence | Log-odds shift from 0.5, any value 0.1–5 | KP's exact intercept per incidence; picker offers only KP's options |
| Bili thresholds | Correct AAP data, but **looked up one hour late** | Matches PediTools at 204/204 sampled points |
| Bili guidance text | Not from any source | AAP 2022 escalation-of-care + discharge follow-up table |

Across 52,416 EOS input combinations, 15% of recommendations changed category.
That includes 619 clinically-ill cases the old code labelled "ROUTINE".

## 1. EOS (Kaiser Permanente sepsis calculator)

### Source of truth

- **2017 (original) model:** KP EMR FAQ,
  https://neonatalsepsiscalculator.kaiserpermanente.org/EmrFAQ.aspx
  (Puopolo et al., Pediatrics 2011, with KP's sign correction for GBS-unknown).
- **2024 (updated) model:** KP 2024 Model Update FAQ,
  https://neonatalsepsiscalculator.kaiserpermanente.org/ModelUpdateFAQ.aspx
  (Kuzniewicz et al., Pediatrics 2024;154(4):e2023065267).
- **Incidence → intercept:** the `ddlIncidence` dropdown on
  `InfectionProbabilityCalculator.aspx`. The 2024 dropdown only appears after
  the AJAX postback that selects the 2024 model.

### Model form (same for both)

```
logit = intercept(incidence)
      + b_temp * TempF                  (°F, 0.1 precision)
      + b_ga * GA + b_ga2 * GA^2        (GA = weeks + days/7)
      + b_rom * (ROM_h + 0.05)^0.2
      + b_abx1 * [GBS IAP >=2h  OR  broad-spectrum 2–3.9h]
      + b_abx2 * [broad-spectrum >=4h]
      + b_gbs_pos * [GBS+] + b_gbs_unk * [GBS unknown]
risk at birth = 1 / (1 + e^-logit)
posterior odds = prior odds × LR(exam)
```

### Coefficients (as published)

| Term | 2017 | 2024 |
|------|------|------|
| Temp (°F) | 0.868 | 0.85194656 |
| GA | −6.9325 | −7.72247124 |
| GA² | 0.0877 | 0.09842383 |
| ROM transform | 1.2256 | 0.86770862 |
| Abx1 | −1.0488 | −2.13142945 |
| Abx2 | −1.1861 | −2.33985917 |
| GBS positive | 0.5771 | 1.02265353 |
| GBS unknown | 0.0427 | 1.13710111 |
| LR well / equivocal / ill | 0.41 / 5.0 / 21.2 | 0.36 / 3.65 / 14.5 |
| GA range accepted by KP | 34–43 w | 35–43 w |

### Intercepts (exact values KP's dropdown submits)

- **2017:** 0.1→38.952265, 0.2→39.646367, 0.3→40.0528, 0.4→40.3415,
  0.5→40.5656, 0.6→40.7489, 0.7→40.903919, 0.8→41.0384, 0.9→41.1571,
  1→41.263432, 2→41.965852, 4→42.676976
- **2024:** 0.05→55.6, 0.1→56.3, 0.2→57.0, 0.27→57.3, 0.3→57.4, 0.4→57.7,
  0.5→57.9, 0.6→58.1, 0.7→58.2, 0.8→58.4, 0.9→58.5, 1→58.6, 2→59.3,
  4→60.0, 5→60.2

Gotchas:
- The 2024 FAQ gives a prior-correction formula (β0 = 57.29929499,
  ȳ = 0.0002763) that yields 57.8926 at 0.5/1000. **The live calculator uses the
  rounded table value 57.9.** Only 57.9 reproduces the scraped data exactly
  (148/148 vs 71/148).
- The 2017 intercepts are **not** an exact log-odds offset of each other
  (they are off by ~0.001–0.016). Use the table, don't derive.
- Off-table incidences (only possible via `config.json`) are interpolated
  linearly in log-odds between neighbouring table entries.

### Recommendation logic (from live KP output, 2026-09-26)

Compared against the rounded (displayed) values:

| Exam | Posterior | Recommendation | Vitals |
|------|-----------|----------------|--------|
| Clinical illness | ≥3 | Empiric antibiotics | Per NICU |
| Clinical illness | <3 | Consider starting empiric antibiotics | Per NICU |
| Well / equivocal | ≥3 | Empiric antibiotics | Per NICU |
| Well / equivocal | 1–2.99 | Blood culture | q4h × 24h |
| Well / equivocal | <1, **risk at birth ≥1** | No culture, no antibiotics | q4h × 24h |
| Well / equivocal | <1, risk at birth <1 | No culture, no antibiotics | Routine |

Observed live cases (all encoded in `eos.test.ts`): ill 0.49 and ill 1.03 →
"Consider starting"; well 0.86 with birth 2.37 → q4h vitals; equivocal 1.06 →
culture; well 15.82 → empiric.

### What was wrong before

- `eos.ts` called itself a "1:1 port" but used coefficients from
  `scripts/fit_eos_regression.py`: a cubic-in-GA least-squares fit to
  heavily rounded outputs (many rows were 0.01–0.02/1000). The abx and
  GBS-unknown terms were each pinned by one rounded data point. For example,
  2024 GBS-IAP was −2.30 vs the published −2.13. The fit script and
  `eos_coefficients.json` have been deleted.
- The recommendation thresholds 0.5 / 1.0 / 3.0 on posterior only came from
  `config.json`, not KP. Clinically ill babies with low posterior got "ROUTINE".
- `scripts/kp-scraper.py`'s `INCIDENCE_2024` table was wrong for every entry
  except 0.5, so scraping at other incidences would have produced bad
  vectors. It is now corrected.

## 2. Bilirubin (AAP 2022)

### Source of truth

- AAP 2022 guideline: Kemper et al., Pediatrics 2022;150(3):e2022058859.
- Reference implementation used for checking: PediTools bili2022,
  `https://peditools.org/bili2022/api/?ga=<int>&age=<int>&risk=none|any`.
  It returns **HTML, not JSON**. Parse the table cell
  `<TD bgcolor='#FFFFFF'>X mg/dL`. It takes integer GA ≥35 and integer age
  1–336h (fractional age is rounded).

### What was wrong before

- The data in `biliThresholds.ts` is correct, but **array index i is hour
  i+1** (the tables start at hour 1). The lookup used `floor(age)` as the
  index, so every threshold was the next hour's value: 0.1–0.2 mg/dL too high
  in the first 96h, the less cautious direction. It is now indexed by
  `round(age) − 1` and clamped to hours 1–336. The threshold-table page labels
  were fixed the same way.
- The follow-up text was invented. It is replaced with AAP 2022 guidance as
  PediTools presents it:
  - At or above the exchange threshold → urgent exchange transfusion.
  - At or above exchange − 2 → escalation of care.
  - At or above the photo threshold → phototherapy, TSB within 12h.
  - Below the photo threshold, the discharge follow-up table by
    photo − TSB (thresholds in mg/dL):
    - under 2 (age under 24h → delay discharge, TSB in 4–8h; otherwise TSB in 4–24h plus options);
    - 2 to under 3.5 → 4–24h;
    - 3.5 to under 5.5 → 1–2 days;
    - 5.5 to under 7 → within 2 days (clinical judgment at or after 72h);
    - 7 or more → within 3 days (clinical judgment at or after 72h).
- GA <35 now carries a warning (AAP 2022 does not apply; the 35w table is
  used).

### Verification

`src/calc/fixtures/peditools-bili2022.json` has 204 PediTools samples: GA 35–40,
both risk groups, ages {1, 6, 12, 18, 24, 36, 48, 60, 72, 84, 96, 120, 144, 168,
216, 264, 335}. All match exactly. Under the old indexing 0 of the 204 samples
were offset-free. With index = hour − 1 all 408 values (photo + exchange) match.

## 3. How it's tested now

- `src/calc/eos.test.ts` loads **every row** of `kp-eos-data.csv` (via
  `?raw` import) and requires exact 2-dp equality for birth, well, equivocal
  and ill. It also covers:
  - the live-KP recommendation cases;
  - the user-reported reference case (39w0d / 37.0°C / ROM 12h / GBS− →
    0.29; 0.10 / 1.06 / 4.19);
  - that the incidence options match KP's dropdowns;
  - the GA range warning.
- `src/calc/bili.test.ts` checks the PediTools fixture, age rounding and
  clamping, and three guidance branches.
- The old code fails 184 of these tests; the new code passes all 285.
- `kp-eos-data.csv` gained two rows from live KP queries: 2024 at 1.0/1000 and
  2017 at 0.2/1000. These validate non-default intercepts.

## 4. Re-verifying in the future

1. **Did KP change the model?** The daily `kp-monitor` workflow fingerprints
   `ModelUpdateFAQ.aspx`. If it fires, re-read the coefficient table and the
   intercept table on that page and on `EmrFAQ.aspx`, and diff them against
   `MODEL_2017` / `MODEL_2024` in `src/calc/eos.ts`.
2. **Spot-check live output.** Run `scripts/kp-scraper.py` (keep its rate
   limit; it carries the KP authorization note) or a few manual entries.
   Append the rows to `kp-eos-data.csv` and run `npm test`. Any mismatch at
   2 dp is a real discrepancy.
3. **Bili.** Re-sample PediTools (one GET per point, ~0.3s apart is polite) and
   regenerate the fixture. Any mismatch means the tables or the indexing
   changed.

### KP TLS gotcha

`neonatalsepsiscalculator.kaiserpermanente.org` serves the wrong intermediate
certificate, so curl, Python and Node fail verification. That is why the
scraper has `--no-verify-ssl`. **Don't disable verification.** Instead complete
the chain from the certificate's AIA URLs:

```bash
curl -sS -o r36.crt http://crt.sectigo.com/SectigoPublicServerAuthenticationCAOVR36.crt
openssl x509 -inform DER -in r36.crt -out r36.pem
curl -sS -o r46.p7c http://crt.sectigo.com/SectigoPublicServerAuthenticationRootR46.p7c
openssl pkcs7 -inform DER -in r46.p7c -print_certs -out r46.pem
cat /etc/ssl/certs/ca-certificates.crt r36.pem r46.pem > kpbundle.pem
curl --cacert kpbundle.pem https://neonatalsepsiscalculator.kaiserpermanente.org/EmrFAQ.aspx
```

(Python `requests` was still flaky with this bundle on some paths; curl was
reliable.)

The 2024 model is selected by an ASP.NET AJAX postback. See
`select_model()` in `scripts/kp-scraper.py`. Send the
`X-MicrosoftAjax: Delta=true` header, and reuse cookies plus
`__VIEWSTATE`/`__EVENTVALIDATION` across requests.

## 5. Decisions made

- **Removed `eos.recommendation_thresholds` from `config.json`** because KP's
  rules are fixed. If institution-specific thresholds are wanted, add them
  back with KP's semantics (culture ≥X, empiric ≥Y, vitals keyed off birth
  risk), not the old posterior-only ladder.
- GA input is bounded to 34–43 and ROM to 0–240, matching KP's validators.

## 6. Known open items (not fixed)

- `src/calc/bili.ts` `fetchBiliFromAPI` (off by default via
  `bili.api_enabled: false`) cannot work as written. It sends decimal GA,
  though the API needs an integer, and calls `.json()` on an HTML response.
  If enabled, it silently falls back to the local tables. Either fix it by
  parsing the HTML with integer GA, or delete it.
- `src/components/InputForm.tsx` and `src/components/ResultPanels.tsx` are
  not imported anywhere (dead code left from before the shell rebuild).
- The bili note header says "AAP 2022 / PEDITOOLS" even though the values are
  computed locally. They now match PediTools exactly, but the label could say
  "AAP 2022 (local)".
